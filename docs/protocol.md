# Agent and host protocol

The agent-facing transport is MCP stdio, implemented with `@modelcontextprotocol/sdk` 1.32.2. Standard output contains MCP messages only. Discovery works with the tray app offline. Source mode reports `HOST_UNAVAILABLE` until manual native startup. The installed bootstrap may start the tray on subscription or explicit preparation, under the owner policy, initially paused. Discovery and status never launch it. Agents receive server instructions, descriptions for every input parameter and typed success responses through MCP; reading repository files is unnecessary for the workflow. The first instruction paragraph fits within 512 characters and includes the capability and peer-trust boundaries, human pause, ownership checks, renewal and cleanup.

## MCP tools

| Tool | Arguments | Result or effect |
| --- | --- | --- |
| `desktop_subscribe` | `name`, absolute `workspace`, optional `resume_token` | Bind the bridge; return `session_id` and private reconnect token |
| `desktop_status` | None | Availability, holder, token/deadline remaining, subscribers, numbered queue and caller identity |
| `desktop_take` | Optional Boolean `wait`, default true | Take free access or join the FIFO queue; false does not join |
| `desktop_heartbeat` | `lease_token` | Reset only the holder's agent heartbeat to 15 minutes; no maximum total hold |
| `desktop_release` | `lease_token` | End the caller's current access and schedule the next eligible waiter |
| `desktop_cancel_wait` | None | Leave the queue while remaining subscribed |
| `desktop_message` | `to_session_id`, `text`, optional Boolean `urgent` | Enqueue peer-authored data in the recipient's mailbox |
| `desktop_messages` | Optional nonnegative `ack_through` | Acknowledge through an observed message ID, then read remaining messages |
| `desktop_unsubscribe` | None | Remove the caller, its queue entry and any held access |
| `desktop_runtime_status` | None | Read exact selection, independent APIs, owner policy, human Quit, and authenticated host readiness without launching |
| `desktop_runtime_prepare` | None | Prepare the selected runtime/start its tray if allowed; cannot select versions, clear Quit, restart a live host, or grant access |

Successful coordination tool results include the current status snapshot. `you.session_id` identifies the caller; proceed only if it matches `holder.session_id`. `lease.token` is the exact value to pass as `lease_token`. `lease.remaining_ms` is measured at the host and is not a promise that a long external action will finish before expiry. A queue position is one-based, or null when not queued. A holder has no queue position.

Every tool advertises an `outputSchema` for its successful `structuredContent`; the SDK validates actual replies against it. The same JSON is also returned as text. The common snapshot describes `instance_id`, `availability`, `user_blocked`, `holder`, `lease`, `queue`, `sessions`, `you`, `unread_messages`, `heartbeat_timeout_ms`, `heartbeat_warning_ms`, `lease_timeout_ms`, `presence_timeout_ms`, `notifications` and `coordination`. A subscription additionally returns `session_id` and private `resume_token`; sending a message adds `sent`; reading messages adds the remaining `messages` with sender, message ID, text and urgency. A successful unsubscribe has `you: null`. Neither two null identities nor a successful take that only queued the caller establishes ownership.

`heartbeat_timeout_ms` is 900,000 and `heartbeat_warning_ms` is `[180000, 60000]`. `lease_timeout_ms` remains a compatibility alias for the same renewable window, not a maximum holding time. `lease.heartbeat_id` identifies the current deadline generation, changing on every accepted heartbeat even within the same clock millisecond. The grant token stays stable during renewal. Transport presence remains 30,000 ms and never resets the holder heartbeat. Nonholders cannot renew; expiry releases access while a still-connected subscription remains eligible to take again.

`notifications` reports `supported`, `adapter` (`codex` or `none`) and `last_status`: `unsupported`, `ready`, `accepted`, `failed` or `suppressed`. Supported means an explicit local integration and client thread metadata are present. It does not prove that the endpoint is currently reachable. Accepted means Codex accepted a submission, not that the model read or acted on it. Failed delivery cannot renew access. Suppressed means an obsolete or ineligible notice was discarded.

Runtime responses instead describe `version`, `source`, `target`, `startup`, `updates`, `signing`, `api`, `host_running`, `human_quit`, `agreement`, and `restart_required`. Readiness and compatibility do not grant desktop access. This connection stays pinned; operator setup affects new connections. The source bridge reports manual startup and local-source trust.

Domain tool errors use `isError: true` with text JSON `{ "error": { "code": "…", "message": "…", "details": { } } }`, outside the success schema. `details` is optional. Relevant codes include `NOT_SUBSCRIBED`, `NOT_HOLDER`, `STALE_LEASE`, `SESSION_EXPIRED`, `SESSION_CONNECTED`, `SESSION_ENDED`, `CLIENT_SESSION_MISMATCH`, `INVALID_ARGUMENT`, `NOT_FOUND`, `CAPACITY`, `MAILBOX_FULL`, `HOST_UNAVAILABLE`, `OUTCOME_UNKNOWN`, `HOST_START_REFUSED`, `HOST_START_FAILED`, `DESKTOP_UNAVAILABLE`, `API_UPGRADE_REQUIRED`, `API_CAPABILITY_REQUIRED`, `API_NEGOTIATION_REQUIRED`, `API_INVALID_OFFER`, `API_INVALID_AGREEMENT`, and `API_RENEGOTIATION_REFUSED`. MCP schema validation separately rejects malformed tool arguments or invalid host results and may return explanatory text. An uncertain reply does not prove that a mutation failed: read current state before retrying. The bridge never blindly replays a mutation.

`redesktop://desktop/status` is a JSON resource supporting MCP resource subscriptions. Semantic state changes, including a new heartbeat generation, notify subscribers to reread it; elapsed countdown milliseconds alone do not generate notifications. Poll tools when a client does not consume resource notifications. Resource notification alone does not activate a model turn. The full workflow belongs to server instructions, with concise safeguards per tool. Some clients append those instructions to every rendered tool description; the server does not control that expansion. Codex's displayed `unknown` connection status also belongs to its runtime-status layer. Tool discovery, an actual successful tool call, native readiness and desktop ownership must be checked separately.

## Reconnect and teardown

Each bridge holds one private connection to the native host. It maintains presence automatically and reconnects after transport loss, using its in-memory resume token. Reconnection does not repeat a take or restore revoked access. A restarted host refuses the old resume token; the bridge registers a new session, then returns the resulting identity in `you`. A stale token from a previous grant or host instance is still invalid.

EOF on the bridge's stdin and SIGINT/SIGTERM close its host connection. A killed bridge loses its socket through OS process cleanup. This says nothing about a TUI exit when another process still owns the bridge; [bridge lifetime](product.md#bridge-lifetime) explains that distinction. A bridge with a live connection does not automatically renew desktop access.

## Codex integration

`re-desktop codex-install --codex <absolute-codex-path> [--home <absolute-CODEX_HOME>] [--socket <absolute-control-socket>] [--mise <absolute-mise-path>]` is an explicit operator action. It registers `re_desktop` through `codex mcp add`, merges only its named cleanup hooks into `hooks.json`, and writes owner-private integration settings in the selected runtime profile. It preserves unrelated hook groups and configuration; rerunning it updates its entries without duplication. Registration persists the selected runtime profile and any explicit `RE_DESKTOP_STORE` override in the MCP environment, so the bridge and cleanup helper agree even when the client starts without the operator shell environment. The default home is `CODEX_HOME` or `~/.codex`. The default socket is `<home>/app-server-control/app-server-control.sock`. Setup never starts or restarts a Codex daemon. Restart the intended daemon and use fresh MCP connections after changing its entry. Cleanup uses the already-installed absolute Node/bootstrap paths even when the MCP launcher uses mise, so the hook cannot trigger mise auto-installation. Rerun integration setup after updating or moving the bootstrap.

When that endpoint is available, installation lists native hooks and trusts only the exact generated SessionEnd/SubagentStop commands and hashes from the intended hook file using `config/batchWrite`. It never bypasses hook trust. `hook_trust: review-required` leaves operator review pending; review the entries in Codex or rerun installation with the intended endpoint running. Changing a hook's command changes its trust hash. For removal, use `codex mcp remove re_desktop`, remove only the hook handlers named `re:desktop session cleanup` from that Codex home's `hooks.json`, and remove the profile's `codex.json` to disable push. Preserve unrelated handlers. Existing bridges need reconnection; removal does not stop the shared native host.

Client-supplied `_meta.threadId` or `_meta["x-codex-turn-metadata"].thread_id` binds a bridge to a path-safe thread ID. Names, workspaces and process listings are never used to guess identity. A different thread on the same connection is rejected. Per-thread cleanup files under private `codex-sessions/` contain the host instance, participant identity and a random cleanup capability. That capability is never returned in MCP results. Public session IDs, lease tokens and the general host token alone cannot retire another participant.

The bridge sends fixed `re_desktop.heartbeat_warning` tool output through Codex's owner-local WebSocket control socket, using the same `turn/start` tool-output primitive as `codex_tui`. It copies no TUI bearer credential. On Windows the official `codex app-server proxy` carries the WebSocket bytes across Codex's rendezvous transport. Unix rendezvous links and their resolved private socket are owner-checked. A submission is bounded to five seconds and rechecks host, holder, session and heartbeat generation before sending. Notices may wake an idle model or reach an active turn. Late notices explicitly direct the model to current status; no delivery or acknowledgment is a heartbeat. Peer-authored mailbox content is never submitted through this route.

SessionEnd runs on graceful root-session shutdown, after MCP teardown; it does not support MCP tool hooks. SubagentStop uses `agent_id` for the child, not the parent's `session_id`. The local `codex-cleanup` command reads bounded hook input and performs authenticated, capability-scoped IPC with a 700 ms socket budget inside the hook's three-second limit. It never acquires a program, starts a host, clears Quit, renews access or stops the shared host. No-host, stale-host and already-clean cases are idempotent no-ops. A successfully retired live bridge cannot re-register that ended session. Switching views, `thread/unsubscribe`, cancellation and hard kills do not reliably trigger graceful cleanup; keep the heartbeat fallback.

## Local host boundary

The tray app alone owns human pause/allow/end controls. Its private IPC uses newline-delimited UTF-8 JSON with request IDs and a 256-bit local bearer token. Unix hosts use an owner-private directory and socket; Windows uses a named pipe plus the same token. The default runtime directory is `~/.re-desktop`; `RE_DESKTOP_RUNTIME` selects an absolute isolated directory for tests or a second installation. It is not a network listener.

The host bounds input frames to 16 KiB, active/grace sessions to 128, names to 100 characters and workspace paths to 2,048 characters. Paths are descriptive metadata and never opened or executed. Frame parsing/authentication and shared-API negotiation happen before a domain operation. Ordinary files and live sockets are not silently replaced during startup. Unix runtime directory, token and socket modes are 700, 600 and 600 respectively. Windows confidentiality relies on the current user's profile directory ACLs and bearer-token custody; hardening against hostile same-account processes is outside this cooperative MVP.

Connection attribution prevents another subscribed session from releasing a holder merely by knowing its public token. A reconnect capability is private and omitted from other sessions' snapshots, menus and verification reports. Same-account processes with access to the runtime credentials are within the local trust boundary. Neither the protocol nor its token creates a sandbox or an OS desktop lock.

## Independent API negotiation

[`api.json`](../api.json) owns the agent application API, host application API, and supported shared IPC versions/capabilities. Standard MCP wire negotiation remains separate. The authenticated IPC `hello` offer contains `shared_apis`, `required_capabilities`, `agent_api`, and `product_version`. The host selects the highest common IPC API and confirms capabilities plus independent agent/host API and product versions. No session is created during negotiation.

Malformed offers, missing capabilities, disjoint versions, and invalid agreements fail before subscription or mutation. Upgrade errors identify `host`, `bridge`, or `either` when determinable. A legacy host that cannot negotiate requires a host upgrade; a legacy bridge cannot operate against the negotiated host. Active sessions must reconnect to change the selected shared API. Product-version equality is never required.

Agents can request preparation only through the saved owner policy. They cannot provide arbitrary origins, versions, shell commands, or trust settings. A compatible existing host is reused; incompatible hosts are rejected rather than force-restarted. Operator setup selects another exact release for new MCP connections. See [distribution](distribution.md) for the upgrade and restart boundary.
